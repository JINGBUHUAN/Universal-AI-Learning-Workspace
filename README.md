Introduction

Universal AI Learning Workspace is a concept for an open, modular, and extensible AI-powered learning environment.

It aims to help users learn almost anything, including professional software, artistic skills, mathematics, science, and languages.

Instead of providing every feature in one large installation, the workspace adopts a modular architecture. Users only download the learning modules and resources they actually need.

Users can also freely choose their preferred AI models, learning resource sources, and optional plugins.

The project originated from a real problem encountered during self-learning: online tutorials often use different software versions from those installed by learners.

This led to a broader question:

What if AI could participate in the entire learning process, rather than simply answering questions?

Core Features

1. Personalized Learning Paths

- Generate learning paths based on individual goals.
- Adapt plans to the user's experience and available time.
- Allow users to confirm learning paths before generating detailed plans.

2. AI Model Freedom

- Support different AI providers and models.
- Allow users to choose cloud-based or local models.
- Choose models according to intelligence, speed, cost, and privacy requirements.

3. Flexible Learning Resource Sources

- Search for tutorials and learning materials.
- Allow users to select their preferred search engines and media platforms.
- Potential sources include Google, YouTube, and other supported platforms.

4. Modular Learning System

The main application should remain lightweight.

Users do not need to download every learning feature when installing the workspace.

The system provides independently downloadable learning modules.

Examples:

- Language Learning: English, Japanese, French, etc.
- Art Learning: Drawing, Sketching, Design, etc.
- Software Learning: Blender, Photoshop, AutoCAD, etc.
- Mathematics: Algebra, Geometry, Calculus, etc.
- Science: Physics, Chemistry, Biology, etc.

Users can select both learning categories and specific submodules.

For example, someone who only wants to learn English and Japanese only needs to install the corresponding language modules.

Other learning modules remain uninstalled until needed.

5. Optional Plugin Ecosystem

Plugins provide additional capabilities rather than entire learning domains.

For example:

- Software Version Compatibility.
- Screen Recognition.
- Additional learning assistance tools.
- External platform integrations.

Users can independently install, update, disable, and uninstall plugins.

6. Interactive Learning Assistance

- Allow users to ask questions naturally.
- Provide contextual explanations and guidance.
- Support visual understanding through screenshots and images where available.

7. Automatic Exercises and Assignments

Generate exercises based on learning progress.

Examples:

- Software: Modeling and design tasks.
- Art: Drawing and composition exercises.
- Mathematics: Calculations and problem-solving.
- Languages: Vocabulary, grammar, reading, and writing.

8. Evaluation and Feedback

- Evaluate submitted assignments.
- Identify mistakes and suggest improvements.
- Adjust future learning plans based on progress.

Modular Architecture

The project follows a three-layer structure:

Core → Learning Modules → Plugins

- Core: Essential application functions.
- Learning Modules: Independently downloadable learning domains and their submodules.
- Plugins: Optional extensions that add specific capabilities.

Additional design principles:

- Download only what is needed.
- Update modules independently.
- Avoid downloading shared dependencies multiple times.
- Allow modules to be installed or removed at any time.
- Preserve learning records when uninstalling modules, if requested.
- Load installed modules only when needed.

Learning Workflow

Set Goals → Generate Learning Path → Find Resources → Learn with AI → Practice → Evaluate → Improve

Project Philosophy

1. Freedom of Learning.
2. Freedom of AI Choice.
3. Freedom of Resource Sources.
4. Modular Installation.
5. Optional Extensibility.
6. User-Oriented Development.
